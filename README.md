# VISOR – Visual Intelligence System for Ocular Rehabilitation

## VISOR Developer Coldstart

> Refer to `VISOR/` as the project root...

Required Technology:
- Android Studio (IDE + Android Device Emulator)
- *VS Code tutorial coming soon* 

1. Clone the repo. If you're a developer, at this step you would want to create a new branch (for whatever iterative feature you are working on).
2. Open Android Studio at the file `/VISOR/frontend/visor/`
3. Optionally, add VISOR's Meta Wearables Developer Center credentials to your `local.properties`. The Meta Wearables SDK (MWDAT 1.0) now comes from Maven Central, so **no GitHub token is needed** any more; a leftover `github_token` line is simply ignored.

```python
# VISOR/frontend/visor/local.properties
# --------------- It should look something like this ↓ ---------------
## This file is automatically generated by Android Studio.  
# Do not modify this file -- YOUR CHANGES WILL BE ERASED!  
#  
# This file should *NOT* be checked into Version Control Systems,  
# as it contains information specific to your local configuration.  
#  
# Location of the SDK. This is only used by Gradle.  
# For customization when using a Version Control System, please read the  
# header note.  
sdk.dir=<absolute path to android SDK>
# From the Wearables Developer Center. Leave both out to use "0", Meta's
# Developer Mode placeholder; "Hey Meta, start VISOR" and release channels
# need the real values with Developer Mode off.
mwdat_application_id=<application id>
mwdat_client_token=<client token>
# Optional: the VISOR backend to call. Leave out to use the hosted server;
# a backend running on this computer is http://10.0.2.2:8000 from the emulator.
visor_api_base_url=<http://host:port>

# e.g.
sdk.dir=C\:\\Users\\visor\\AppData\\Local\\Android\\Sdk  # WINDOWS
```

**That's it!** 

After you let your Gradle sync in Android Studio, you may connect an android device (with developer mode enabled) or use the android device emulator to run, debug, and test VISOR. 
 > You can change the build variant type from `debug (default)` to `release`  from **Build** > **Select Build Variant...** if needed. This may require **Build > Clean Project** and **Build > Assemble 'app' Run Configuration** to prevent errors.

In essence, this is the developer guide in setting up the VISOR application for development and testing. We highly recommend becoming familiar with the **Kotlin** language and **Jetpack Compose** (its UI toolkit). See below for other developer guides.

More on how we setup and use the Meta Wearables Device Access Toolkit:
> See [Meta Wearables Device Access Toolkit for Android](https://github.com/facebook/meta-wearables-dat-android) GitHub Repository. This also includes guides to getting any AI-Assisted Development started.
> See [Meta DAT Integration Documentation](https://wearables.developer.meta.com/docs/develop/dat/build-integration-android) for the Kotlin documentation.

## Project Layout

A quick reference for where things live. Each row is one folder and what belongs in it.

```
VISOR/
├── frontend/visor/          Android app (Kotlin + Jetpack Compose + Meta Wearables DAT)
├── frontend/visor-webapp/   IMU Lab web app for the Ray-Ban Display glasses (hosted on Vercel)
├── backend/                 FastAPI server: accounts (Supabase), scene descriptions (VLM), depth
├── analysis/                Python analysis of head-motion (IMU) recordings
├── tools/kws/               Wake-phrase tooling ("VISOR, read this", "VISOR GO")
├── documentation/           Developer guides, research, test protocols
├── data/                    Local IMU recordings (gitignored)
├── .github/workflows/       CI: Android build + unit tests on pull requests; changelog summarizer
└── CHANGELOG.md             Written by the summarizer on each push to main
```

### Android app: `frontend/visor/app/src/main/java/ucf/visor/`

| Package | What it holds |
| --- | --- |
| `MainActivity.kt` | Entry point: permissions, Meta Wearables setup, and routing each wake phrase to its feature. |
| `capture/` | The three camera features: `TextReader` (read text), `ObjectIdentifier` (name objects), `SceneDescriber` (describe the scene). Each takes one photo with the glasses (`GlassesPhotoSource`); without glasses, pair mock glasses in the debug menu and choose the photo they take. |
| `recognition/` | On-device ML Kit recognition: text (`TextReaderOCR`), object labels (`ObjectDetector`), custom labels (`CustomObjectDetector`, not wired up yet). |
| `network/` | Every backend call: `ApiClient` (server address, shared HTTP client), `AuthApi`, `VlmClient`. |
| `data/` | What is saved on the phone: the login session (`SessionStore`) and the accessibility profile (`ProfileStore`, `UserProfile`). |
| `stt/` | Listening: wake phrases (sherpa-onnx) and spoken commands. |
| `tts/` | Speaking: `Speaker`, the "thinking" beep, and `SpokenPhrases` (everything the camera features say). |
| `wearables/` | Meta glasses helpers: `GlassesLease` (who holds the glasses' one session), device status, spoken session errors, "Hey Meta" launches. |
| `motionlab/` | Head-motion research lab: Motion and camera trials, recordings (debug menu → Test Suite). |
| `ui/` | `VisorLayout` (watches state and navigates) and `VisorNavHost` (one route per screen). |
| `ui/screens/` | One folder per screen, plus any ViewModel used only by that screen (e.g. `debug/DebugViewModel`): `title/`, `auth/`, `home/`, `hardware/` (Pair Glasses), `profile/` (setup wizard, Settings), `help/`, `motionlab/`, `debug/`, `phase1/`. |
| `ui/viewmodel/` | `VisorViewModel` and `VisorUiState`: app-wide state and navigation requests. |
| `ui/components/` | Shared widgets: buttons, text fields, header, navigation bar. |
| `ui/glasses/` | Navigation rendered on the glasses' display and driven by taps. |
| `ui/voice/` | "VISOR GO" voice navigation commands. |
| `ui/theme/` | Colors, Atkinson Hyperlegible type, high-contrast themes, text scaling. |

| Other app folders | What they hold |
| --- | --- |
| `app/src/main/res/values/strings.xml` | On-screen text; new text goes here (see [frontend-jumpstart](./documentation/developer/frontend-jumpstart.md)). |
| `app/src/main/assets/kws/` | The wake-word model, and its phrase list `keywords.txt` (generated by `tools/kws`). |
| `app/src/test/` | JVM unit tests (`./gradlew testDebugUnitTest`). |
| `app/src/androidTest/` | On-device tests: mock glasses (MockDeviceKit) and registration. |
| `gradle/libs.versions.toml` | Every dependency version, in one place. |

### Backend: `backend/`

| Folder | What it holds |
| --- | --- |
| `main.py` | The FastAPI app; mounts the routers. |
| `routes/` → `services/` → `schemas/` | Endpoints, the logic behind them, and their request bodies. |
| `services/vision_language_models/` | One class per vision language model (Qwen, Gemma, Moondream). |
| `scripts/`, `samples/` | Try a model without the server, and the test images it uses. |
| `notebooks/`, `weights/`, `other/` | Exploration notebooks, kept YOLO weights, and the custom detector trainer draft. |

Endpoints and setup: [backend/README.md](./backend/README.md).
